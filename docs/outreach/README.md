# Outreach templates

Templates for contacting research labs, maintainers, and prospective
contributors. **Sending anything is a human action.** Nothing here is automated,
and nothing here should be sent without reading it first.

## The rule these are written under

> No outreach may claim an existing partnership, adoption, or endorsement.

That is not a style preference. A quantum-computing project writing to a
research group is asking for time from people who can check every claim, and one
inflated sentence costs more credibility than the entire message buys.

It is also, right now, a rule with teeth, because the project has very little to
inflate. As of the last collection:

|---|---|
| stars | 1 |
| contributors | 2 |
| external contributors, last 12 months | 1, most recently 173 days ago |
| published releases | 0 |
| npm / PyPI | not published |
| independent reproductions | none |

Current figures are at [ketqat.com/metrics](https://ketqat.com/metrics), and are
regenerated by `scripts/collect-oss-metrics.mjs`.

A project in that position has exactly one honest pitch: **here is what it does,
here is what it refuses to do, and here is how you can check.** That is the shape
every template below takes.

## What may not appear

`scripts/verify-outreach-claims.mjs` runs in CI over this directory and refuses:

- claims of partnership, collaboration, or affiliation with any named institution
- claims that anyone uses, has adopted, endorses, or recommends the project
- "trusted by", "used by", "backed by", "in production at"
- adoption or download figures written as prose
- superlatives about being first, only, leading, or best
- the word "we" attached to an organisation that does not exist

It cannot judge whether a specific sentence is true. It can stop the specific
false sentences that outreach writing reaches for by reflex, and it does.

## What may appear, because it is verifiable

- The QEC path runs **real Stim sampling and PyMatching decoding**. There is no
  synthetic fallback: without the dependencies the run fails and says so.
- A logical error rate from a run with no observed failures is reported as an
  **upper bound**, never as zero, everywhere it is displayed.
- Runs that measured different experiments are **refused a comparison** rather
  than ranked.
- Every result carries a reproducibility hash the server independently
  recalculates on import.
- Apache-2.0, vendor-neutral, no provider lock-in.

Each of those is a property of the code, and each is checked by a test. Anyone
can verify them in about a minute — the quickstart is 21 seconds.

## Known weaknesses, which you should disclose rather than hide

If you are writing to someone whose time you want repeatedly, name these before
they find them:

- **The same experiment run twice currently produces different reproducibility
  hashes** (ketqat-sdk#89). Duration measurements sit inside the hashed payload.
  This is a real defect in the project's headline property and it is open.
- Nothing is published to a package registry yet, so installation means building
  from source.
- The web application is closed-source, so contributions to the site are not
  possible today.

Leading with a known bug is not weakness. It is the fastest way to establish
that the rest of the message can be believed.
